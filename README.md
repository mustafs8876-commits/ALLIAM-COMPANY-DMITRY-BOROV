# ALLIAM — личный сайт с заявками в Telegram

Готовый адаптивный сайт ALLIAM: фотографии, услуги, FAQ, описание специалиста, страница конфиденциальности и **настоящая серверная отправка формы в Telegram** через Vercel Function. Без платного сервиса e-mail и без хранения токена бота в браузере.

## Важно: если под заявкой написано `Failed to fetch`

Это ошибка соединения браузера с `/api/contact`, а **не подтверждённая ошибка Telegram**.

1. Если вы открыли `index.html` двойным нажатием (`file:///...`) — автоматическая отправка не работает. Нужен развёрнутый сайт с Vercel Function.
2. Если сайт запущен через Live Server, `python -m http.server` или `npm run preview:static` со статическим сервером — HTML работает, но `/api/contact` отсутствует. Локально запускайте `vercel dev` (в каталоге проекта), а в интернете публикуйте через Vercel.
3. Если сайт уже на Vercel, откройте `https://ВАШ-ДОМЕН/api/contact`. Ожидаемый ответ: `{"ready":true,"captchaRequired":false}`. Если 404 или HTML — не опубликована серверная папка `api/`/неверный Root Directory. Если `ready:false` — добавьте `TELEGRAM_BOT_TOKEN` в Settings → Environment Variables и сделайте Redeploy.
4. Начните диалог с ботом (`/start`) из нужного Telegram-профиля. Затем отправьте тестовую заявку. Если сервер возвращает 502 — смотрите ошибки доставки и проверьте chat_id, бота и секрет.
5. Если автоматический способ недоступен, сайт теперь **блокирует ложную отправку**, показывает причину и кнопку «Открыть Telegram». Клиент может скопировать текст обращения и самостоятельно вставить его в чат. **Это ручная отправка, она не заменяет автоматическую.**

Никакой ключ не вставляйте в `script.js`, `config.js` или GitHub. Опубликованный в чате токен необходимо отозвать в BotFather и заменить на новый непосредственно в Vercel.

## Как работает заявка

1. Посетитель вводит имя, e-mail/телефон/@Telegram, тему и описание ситуации, подтверждает согласие.
2. Браузер отправляет запрос `POST /api/contact` **на тот же сайт**, не на Telegram напрямую.
3. Сервер проверяет формат, согласие, антиспам; при включении Turnstile — проверяет токен на стороне сервера.
4. Сервер использует приватный `TELEGRAM_BOT_TOKEN`, чтобы передать заявку на текущий ID `5675498860` (или ID из `TELEGRAM_CHAT_ID`) через официальный Telegram Bot API `sendMessage`.
5. Только после `ok: true` и `message_id` Telegram клиент видит: **«Заявка №... доставлена в Telegram»**. В противном случае текст остаётся в форме; его можно скопировать для ручной отправки.

Формат сообщения в чате: номер заявки, время, имя, контакт, тема, текст; если посетитель оставил Telegram username, появляется кнопка «Написать в Telegram». Бот не может написать посетителю самостоятельно, пока тот не открыл с ним чат; кнопка открывает профиль человека для ответа с вашего аккаунта.

## 1. Создайте Telegram-бота

1. В Telegram откройте **[@BotFather](https://t.me/BotFather)** (проверьте официальное имя).
2. Нажмите **Start**, отправьте `/newbot`, придумайте имя и уникальный username, оканчивающийся на `bot`.
3. Скопируйте токен вида `123456789:AAAA...`. Это **секрет**: не публикуйте, не отправляйте в чаты и не вставляйте в `config.js`, HTML, GitHub или скриншоты.
4. Откройте созданного бота, отправьте `/start`. Это обязательно, чтобы бот мог отправлять вам сообщения в личный чат.
5. Для личного диалога пользователя с ботом **Telegram ID профиля совпадает с ID приватного чата**, но только если пользователь уже открыл этого бота и отправил ему `/start`. Для ALLIAM временный получатель уже указан в `api/contact.js`: `5675498860`. Для другого чата можно установить `TELEGRAM_CHAT_ID` на Vercel.

Для отдельной группы: добавьте бота в нужную группу, отправьте в группе любое сообщение, используйте её отрицательный `chat_id`. Для форумной темы можно задать `TELEGRAM_THREAD_ID`. Лучше создать **отдельного бота для заявок**. Если у бота уже есть webhook и обработка сообщений в другом проекте, команда `getUpdates` может не работать — не удаляйте чужой webhook ради сайта.

### Узнать chat ID и протестировать бота через терминал (Node.js 20+)

В распакованной папке проекта в PowerShell или терминале задайте переменные **локально**, не записывайте токен в код и не коммитьте его:

```powershell
$env:TELEGRAM_BOT_TOKEN = "ВАШ_ТОКЕН_ОТ_BOTFATHER"
npm run telegram:check
```

После `/start` команда покажет обнаруженные чаты и их ID (`TELEGRAM_CHAT_ID=...`). Если новых обновлений нет, отправьте боту ещё одно сообщение и запустите снова.

Далее в этом же окне:

```powershell
$env:TELEGRAM_CHAT_ID = "ВАШ_ЧИСЛОВОЙ_CHAT_ID"
npm run telegram:check
```

Придёт тестовое сообщение в Telegram. **Не вводите реальные данные клиентов при тесте.** Для групповых тем также задайте `TELEGRAM_THREAD_ID`.

## 2. Загрузите сайт на Vercel

**Через GitHub — предпочтительный способ:**

1. Создайте репозиторий https://github.com/new (например `alliam-website`).
2. Распакуйте архив и загрузите **все файлы, в том числе папку `api/`**, в корень репозитория; в корне должен быть `index.html`.
3. Откройте https://vercel.com/new, импортируйте репозиторий.
4. Framework Preset: `Other`; Root Directory: `./`. Для статического сайта нет Build Command/Output Directory override. Папка `/api/` автоматически станет серверной функцией.
5. В **Vercel → ваш проект → Settings → Environment Variables** добавьте:

| Имя | Значение | Обязательность |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | Секретный токен от BotFather | **Да** |
| `TELEGRAM_CHAT_ID` | ID получателя; если не задан, используется `5675498860` | Нет, для смены получателя |
| `TELEGRAM_THREAD_ID` | ID темы в группе-форуме | Только для тем |
| `TURNSTILE_SECRET_KEY` | Приватный ключ Cloudflare Turnstile | Рекомендуется на публичном сайте |
| `UPSTASH_REDIS_REST_URL` | URL базы Upstash Redis | Необязательно |
| `UPSTASH_REDIS_REST_TOKEN` | Ключ доступа Upstash Redis REST | Необязательно |

6. Выберите окружение **Production** и, если нужен тестовый адрес, **Preview**. Выполните **Redeploy**: новая версия сервера должна получить переменные. Изменение env не обновляет уже запущенную версию.
7. Обязателен `TELEGRAM_BOT_TOKEN`. Если используете текущий личный аккаунт `@rolexgolda_shop`, он должен сначала открыть бота и отправить `/start`. Перейдите на `https://ВАШ-САЙТ.vercel.app/api/contact` — после настройки увидите `{"ready":true,"captchaRequired":false}` (либо `true` для captchaRequired, если включён Turnstile). Это показывает наличие обязательных настроек, а не гарантирует корректность токена/чата.
8. Отправьте с сайта тестовую заявку и проверьте Telegram. Убедитесь, что бот получил `/start` и chat ID правильный. Окончательная проверка — сообщение реально пришло.

> **Важно:** для работающих серверных функций используйте GitHub Import или официальный Vercel CLI (`vercel --prod`) из корня проекта. Не публикуйте только отдельный HTML-файл или папку `assets/`. Обычный статический хостинг без Node.js/Vercel Functions не доставит заявки в Telegram.

## 3. Защита от спама

В базовой версии уже включены скрытое ловушечное поле, строгая проверка данных, ограничение размеров, проверка Origin браузера и отсутствие публичного токена.

Для публичного сайта настоятельно рекомендуем бесплатную **Cloudflare Turnstile**:

1. Создайте Widget на https://dash.cloudflare.com/ с разрешёнными доменами вашего сайта (включая основной `*.vercel.app` адрес / ваш домен, как поддерживается интерфейсом Cloudflare).
2. В `config.js` впишите **публичный** `turnstileSiteKey` (публиковать его безопасно).
3. В переменные проекта Vercel внесите **секретный** `TURNSTILE_SECRET_KEY`.
4. Отправьте новую версию. Сайт сам покажет проверку, сервер проверит токен Cloudflare перед каждой отправкой.

**Задавайте оба ключа одновременно**: если секрет задан, а публичного ключа нет, клиент не сможет пройти защиту. Не путайте публичный site key и приватный secret.

Для ограничения объёма сообщений ещё можно подключить Upstash Redis REST: в Vercel добавить `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN`. Тогда действует лимит **5 обращений в час на IP**. Без Upstash лимит по IP не применяется — в бессерверном окружении нельзя надёжно хранить счётчик только в памяти. При временном сбое Redis заявки остаются доступными, поэтому Turnstile рекомендуется как вторая защита.

## Публичные контакты

В `config.js` можно указать:
- `telegram` — публичный username для ручного обращения (без `@`);
- `email` и `phone` — дополнительные способы связи;
- `turnstileSiteKey` — только публичный Cloudflare site key.

`TELEGRAM_BOT_TOKEN` и `TURNSTILE_SECRET_KEY` **никогда не размещайте в этом файле**. Временный ID получателя уже указан в `api/contact.js` (`DEFAULT_CHAT_ID`), а изменить его можно через Vercel `TELEGRAM_CHAT_ID` без изменения файлов.

## Локальная проверка и тесты

```bash
npm test
```

Тесты проверяют ответы сервера, отказы при ошибках, защиту от поддельных HTML-тегов, отправку в Telegram, Cloudflare и лимиты через **тестовые ответы**, без отправки настоящих сообщений и без реальных токенов.

Для полной локальной проверки Vercel-функции используйте `npm start` (запускает Vercel CLI `vercel dev`) и локальный `.env` (этот файл игнорируется Git). Для просмотра статических страниц достаточно `npm run preview:static`, но такой сервер **не исполняет** `/api/contact`.

## Защита персональных данных

Операторы сайта должны дополнить `privacy.html` данными о владельце, адресом для запросов, правовыми основаниями и сроками хранения до публичного запуска. Заявки передаются в Telegram — не размещайте в них паспорта, пароли, данные банковских карт и полные конфиденциальные документы. Защитите Telegram-аккаунт двухфакторной аутентификацией и ограничьте доступ участников к чату с заявками. Оцените требования GDPR и законодательства применимой страны.

## Файлы

- `index.html`, `styles.css`, `script.js` — сайт и форма;
- `config.js` — только публичные настройки;
- `api/contact.js` — серверная отправка Telegram, временный ID получателя `DEFAULT_CHAT_ID`, защита от спама;
- `scripts/telegram-check.js` — проверка токена, chat ID и тестовая отправка;
- `tests/contact.test.js` — автоматические тесты;
- `.env.example` — имена переменных (примеры, **без настоящих секретов**);
- `vercel.json`, `package.json` — Vercel и Node.js;
- `privacy.html` — шаблон политики конфиденциальности.

## Быстрая настройка ALLIAM для @rolexgolda_shop

**Уже сделано в коде:** `config.js` → `telegram: "rolexgolda_shop"` (публичный контакт); `api/contact.js` → `DEFAULT_CHAT_ID = "5675498860"` (ID получателя).

**Остался один обязательный секрет на Vercel:** Project → Settings → Environment Variables → `TELEGRAM_BOT_TOKEN` → ваш токен из @BotFather. Если токен когда-либо попал в переписку, отзовите его через `/revoke` в @BotFather и используйте новый только в Vercel.

**Не забудьте:** с Telegram-аккаунта `@rolexgolda_shop` открыть бота и отправить `/start`, затем после добавления переменной перезапустить деплой и отправить тестовую заявку. Никакой токен нельзя вставлять в репозиторий, в `config.js`, HTML или `api/contact.js`.

**Если изменится получатель:** проще всего добавить в Vercel `TELEGRAM_CHAT_ID` с новым ID; это переопределит временный ID из кода.
